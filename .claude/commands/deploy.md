# /deploy — Vercel Deployment Workflow

Full deployment pipeline for this Gatsby portfolio to Vercel, with pre-deployment validation, deployment execution, and post-deploy verification.

## Usage

```
/deploy [--env preview|production] [--skip-build] [--rollback] [--check]
```

**Examples:**
- `/deploy` — full pre-flight + production deploy
- `/deploy --env preview` — deploy preview branch
- `/deploy --check` — run pre-deployment checks only (no deploy)
- `/deploy --skip-build` — deploy already-built `public/` to Vercel
- `/deploy --rollback` — instructions to roll back to previous deployment

## Pre-Deployment Checklist (always run)

### 1. Code Quality Gate
- [ ] `npx eslint src/ --max-warnings 0` passes with zero errors.
- [ ] No `console.log` / `console.error` left in `src/` (search and report).
- [ ] No hardcoded localhost URLs in `src/` (search for `localhost:8000`).
- [ ] No sensitive data in source files (API keys, tokens, personal emails beyond config.js).

### 2. Content Integrity
- [ ] All featured project `cover` images exist in their respective `content/featured/*/` folders.
- [ ] All job entries have valid `range` and `date` fields.
- [ ] All external/GitHub URLs in frontmatter are well-formed HTTPS URLs.
- [ ] `static/resume.pdf` exists and is up to date.

### 3. Configuration Checks
- [ ] `src/config.js` — email, social URLs, nav links are current.
- [ ] `gatsby-config.js` — `siteMetadata.url` matches production URL.
- [ ] `gatsby-plugin-google-analytics` tracking ID is set (if used).
- [ ] `vercel.json` exists and is valid JSON.

### 4. Build Validation
- [ ] Run `gatsby clean && gatsby build` — must complete without errors.
- [ ] `public/index.html` exists after build.
- [ ] `public/sitemap/` generated by gatsby-plugin-sitemap.
- [ ] No 404 pages in the build (check `public/404/index.html` is generic, not a real page).

### 5. Performance Gate
- [ ] Review bundle sizes (JS should be < 500KB gzipped total for main page).
- [ ] Verify `public/static/` contains processed images (Sharp worked).

## Deployment Process

### Via Vercel CLI (if installed)
```bash
# Preview deployment
vercel

# Production deployment
vercel --prod
```

### Via Git Push (auto-deploy)
```bash
git add -A
git commit -m "deploy: <description of changes>"
git push origin main
```
Vercel auto-deploys on push to the main branch (configured in Vercel dashboard).

### Verify vercel.json
The portfolio's `vercel.json` should include:
```json
{
  "buildCommand": "gatsby build",
  "outputDirectory": "public",
  "framework": "gatsby",
  "headers": [...]
}
```

## Post-Deploy Verification

After deployment completes, verify:
1. **Homepage loads**: Visit production URL.
2. **Nav links work**: About, Experience, Work, Contact anchors scroll correctly.
3. **Resume PDF**: `https://[domain]/resume.pdf` downloads correctly.
4. **Featured projects**: Images load (check cover.png paths).
5. **Contact section**: Email link is correct.
6. **Mobile**: Check responsive layout at 375px width.
7. **Sitemap**: `https://[domain]/sitemap/sitemap-index.xml` returns XML.
8. **Security headers**: Verify via https://securityheaders.com (if headers configured).
9. **Lighthouse audit**: Run via Chrome DevTools on production URL — record scores.

## Rollback Procedure (`--rollback`)

Vercel preserves all previous deployments. To rollback:
1. Go to Vercel Dashboard → Project → Deployments.
2. Find the last stable deployment.
3. Click "..." → "Promote to Production".
4. Or via CLI: `vercel rollback [deployment-url]`

## Environment Variables

If any env vars are needed (Google Analytics ID, etc.):
- Set in Vercel Dashboard → Project → Settings → Environment Variables.
- Never commit env vars to the repo.
- Reference in `gatsby-config.js` via `process.env.VARIABLE_NAME`.
- For `gatsby develop`, use `.env.development` (must be in `.gitignore`).

## Deployment Environments

| Environment | Trigger | URL Pattern |
|-------------|---------|-------------|
| Production | Push to `main` | `mndportfolio.netlify.app` (or custom domain) |
| Preview | Push to any branch | `*.vercel.app` |
| Local dev | `gatsby develop` | `localhost:8000` |

## Behavioral Flow

1. **Check mode** (`--check`): Run all pre-deployment checks, report pass/fail. Stop here.
2. **Default mode**: Run checks → build → report build success → confirm deploy → execute.
3. **`--skip-build`**: Run checks (skip build step) → confirm → deploy `public/`.
4. **`--rollback`**: Show rollback instructions, do not auto-execute.

## Safety Boundaries
- Never force-pushes to `main`.
- Never commits secrets or `.env` files.
- Always requires build success before deploying (unless `--skip-build`).
- Confirms with user before triggering production deployment.
- Never modifies Vercel project settings programmatically.
